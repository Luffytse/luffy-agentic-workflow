# Continuation

Read from step 1 of `implement-spec` when it says so: a foreign ticket (a ticket labelled for another agent), a continuation handoff, a Worker start, or a closed Spec with an open ticket. Everything below is part of that step; "step N" means the step of `implement-spec`'s `SKILL.md`.

**Owner.** You own the Spec, by step 1's owner record, unless handed one ticket under it (**Worker**). When a foreign ticket reaches the frontier, ask your coordinator (the user, when none runs) to start its label's agent on it, and post a **Continuation handoff** comment on the ticket: the Spec, the agent label, the pushed Spec branch, the Spec pull request (or "none yet"), the landed tickets, the evidence owed, the owner (the thread and contact in your owner record), and that you keep the Spec pull request, its review and its merge. The ticket stays in the task graph, blocking what it blocks, and you wait for its worker's report as for an Implementer's. A handoff already posted for an unlanded ticket is out: post no second one and ask for no second start; on re-entry, read the ticket's comments and ask the coordinator for that worker's state, asking again for a start only when it reads the worker as ended without landing the ticket, or the handoff is an incomplete one (no worker started). It lands when its squash commit is on the pushed Spec branch and its ticket-check record exists: read the record, never repeat the check (its open Findings go to Round 1), check the worker's evidence as step 4 does (gaps go back to it), and handle it, its evidence and Door call and the ticket's `Closes` lines as step 6.5 does a check you kept (a record on the ticket is posted on the draft). Before each landing of your own, fetch the Spec branch and merge in what the other agent pushed (never a rebase).

**Worker.** Handed one ticket under a Spec (with a Continuation handoff, or by `implement`) whose owner the handoff, a Spec pull request or the coordinator names, run this skill for that one ticket only: step 1's check against main for it, steps 3 to 5 off the pushed Spec branch, then step 6.1 to 6.4, fetching the Spec branch first (a rejected push as step 2 says). Record its ticket check on the Spec pull request (on the ticket while no draft is open), comment the landed commit, the check's link, the evidence (as step 4 checks it) and the one-way-door call on the ticket, report to whoever started you and to the owner the handoff names, and stop: you open, ready, review or merge no Spec pull request and build no other ticket. When no owner is named or the owner is unreachable, ask the coordinator; you become the owner only once it confirms, posting an owner record as step 1 says and keeping every landed ticket.

**Closed Spec, open ticket.** If the Spec is closed (its pull request merged) while a ticket left in the task graph has not landed: reopen the Spec with a comment naming the open tickets and the merge; recreate the Spec branch, same name, from current main (if it still exists, merge main into it), so landed tickets come from main and are never rebuilt; build only the remaining tickets, foreign ones by continuation; and open a **continuation Spec pull request** whose `Closes` lines are the Spec and the remaining tickets only, reviewed and merged as steps 7 and 8. There "landed" in steps 6.5 and 8.1 means landed since the branch was recreated, so earlier tickets' lines stay out.

**No dispatch.** If no coordinator can start the agent a foreign ticket needs, or ownership cannot be confirmed, leave it unbuilt and post an **incomplete handoff** on it: the handoff record plus what is missing (who must run which agent). The Spec pull request stays a draft and the Spec open; build what it does not block and report it at step 9 as waiting. It stays in the task graph until it lands or the user drops it.
