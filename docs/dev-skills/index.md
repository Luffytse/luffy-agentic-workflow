# Docs index

Read this first, then open only the docs whose line fits your work. Specs and tickets are GitHub issues, not files here. Bare issue and pull request numbers in text written before the move on 2026-11-05 (ADRs 0001 to 0013, changelog entries before the move entry, and the issues moved from the archive, which link their original) refer to the private archive `Luffytse/luffy-dev-skills`; from the move on, a bare number means this repo's issue, and a reference to an archive issue is written in full as `Luffytse/luffy-dev-skills#<n>`. The commits recorded for past Releases are the archive's IDs, not this repo's (ADR 0014).

- [ADR 0013](adr/0013-skill-changes-are-tested-by-ci-evals-and-review.md): the earlier three layers (CI, model evals, review); replaced by ADR 0015 and kept as history. Read when asking how skill changes were tested before ADR 0015.
- [ADR 0015](adr/0015-model-evals-are-retired-and-skill-changes-merge-on-ci-review-and-acceptance-lines.md): why model evals were retired (they had grown to about 420,000 words and no decision of the skill walk rested on one), what replaced them (a skill change merges on CI green, the review and each acceptance line of its issue shown as met in the pull request body; real-project gaps come back as Retro issues; CI and Review as the two layers), and what was considered (a small core of kept cases, keeping the folder with no rule). Read when changing how a skill change is tested or shown ready to merge.

## Packaging

- [README.md](../../README.md): Claude Code and Codex marketplace install, update and local-development steps. Read when changing install steps.
- [LICENSE](../../LICENSE): the MIT license for our own work; the Upstream notice is `plugins/dev-skills/LICENSE-mattpocock-skills`. Read when asking what the repo's license covers.
- [dev-skills README](../../plugins/dev-skills/README.md): what the plugin is, Claude Code and Codex install, update and local-development steps, the folder layout and the last Upstream commit looked at. Read when installing the plugin or adding a skill of our own.
- [scripts/run-tests.sh](../../scripts/run-tests.sh): the test runner CI runs once the workflow step that calls it is in place (committed by hand). A test is any file named `test*` under `scripts/` only, not in a `__pycache__` folder; `.sh` runs with bash and `.py` with python3, a `test*` file with another extension fails and is named, and a tree with no test under `scripts/` fails. It exits non-zero naming each failure; a new test joins by its file name alone ([scripts/test-run-tests.sh](../../scripts/test-run-tests.sh) tests it). Run before pushing.
- [scripts/test_review_briefs.py](../../scripts/test_review_briefs.py): scratch-repo tests of the plugin's brief script `review_briefs.py` (`round1`, `ticket`, `fixed`, `later`, `verify`, `disputes`): the Finders each level writes, each brief's sections read from the skill files the way the script reads them (never a sentence of their wording), Always check lines by file globs and by a candidate's Bug class, the Report format check of Finder reports, usage errors and an output directory in the work tree refused, only `git` called. Read when changing `review_briefs.py` or the brief files it cuts from.
- [scripts/test_snapshot.py](../../scripts/test_snapshot.py): tests of the plugin's `team-lead` snapshot command `snapshot.py` on disposable git repos with a local Markdown tracker or a stubbed `gh`: each verdict, a lost report found by the branch, the `reported` and `resumed` fields, and the hand-read fallback. Read when changing `snapshot.py`.
- [scripts/test-check-plugin.py](../../scripts/test-check-plugin.py): the checker's own tests in disposable repositories: a hidden or visible skill passes, and every named check fails on a planted bad case (a stray file or a folder with no `SKILL.md`, a frontmatter name off its folder, a broken skill link, a missing changelog or repository field, Codex version or marketplace drift, a missing release skill, release doc, Boundary seed or record, disabled model or implicit invocation, missing or misnamed agent metadata, a vendor model name, a person's name, a repo-only name, an agent-only label string, a cited tracker operation the seed lacks, a `worker-control` method or fact with no doc link, a harness tool named in `team-lead` or `milestone`, a skill file over 4,000 words). It pins no shipped skill's wording. Run by `scripts/run-tests.sh`, or alone when changing those checks; fresh-runtime dependency application is a separate gate.
- [scripts/check-public-history.py](../../scripts/check-public-history.py): the pre-publish check for the move to the public repo (Spec #712): walks every commit of a repo (all refs, or `--ref`) and fails, naming the commit and what it found, on a file under `plugins/dai-portal-data/`, a personal author or committer email (anything but the GitHub and Anthropic no-reply addresses), a known personal email, Mac hostname or dai-portal database name in a message or file, a claude.ai session or project link, a session, Claude Code session (`cse_`) or trigger (`trig_`) id or a session trailer, or a macOS home-folder path; passes on a clean history. It holds no private value: it derives them at run time from the checked repo and each `--source` (the unrewritten clone), plus an uncommitted `--terms` file, and prints how many it derived; its header says how. Checking an already-rewritten repo needs `--source` pointing at a full clone of the private repo; with no personal email derived it prints a WARNING. Tested by [scripts/test-check-public-history.py](../../scripts/test-check-public-history.py) in disposable repositories (each planted trace fails naming its commit, a clean history passes, the scripts' own text passes). Read before publishing a rewritten history.
- [scripts/rewrite-public-history.py](../../scripts/rewrite-public-history.py): the history rewrite the user runs on a fresh full clone on the Mac (Spec #712): prints the steps first, clones one branch into a new folder, runs `git filter-repo` (drops `plugins/dai-portal-data/`, maps every email but the no-reply ones to the owner's GitHub no-reply address, scrubs session links, session, `cse_` and `trig_` ids and trailers, home-folder paths, personal emails, hostnames and database names from messages and text files, keeps messages and Co-Authored-By lines otherwise), runs the pre-publish check on the result, and pushes only main to `--push-url` only if it passes; `--dry-run` pushes nothing. Tested by [scripts/test-rewrite-public-history.py](../../scripts/test-rewrite-public-history.py) against a seeded repo and a local bare remote (skipped where `git filter-repo` is not installed). Read before running the move's history push.
- [scripts/check-plugin.sh](../../scripts/check-plugin.sh): this repo's own checker for the `dev-skills` layout and repo-wide rules (no vendor model names outside the `model-tiers` skill, no person names, no repo-only text in skill text, operations cited as the tracker doc's **Name** or "Name" operation existing in the tracker doc seed, skill name matching its folder, Codex packaging matching Claude Code and sharing its skills tree, each `worker-control` reference method and Harness fact citing a doc page, the `team-lead` skill naming no harness tool, the `milestone` skill naming `team-lead` and holding no harness tool or delivery record kind, no skill file over 4,000 words except the known ones, which may not grow); its header lists the checks, each identified by a name, never a number. A check tests structure and banned names, never that a skill holds a given sentence, so rewording a skill fails CI only if it adds a banned name. It lives outside the plugin so it does not ship to projects. Read when adding or changing a check, or before pushing a plugin change.
- [ADR 0001](adr/0001-dev-skills-is-one-plugin-forked-from-matt-pocock.md): why `dev-skills` is one plugin that began as Matt Pocock's skills and is now our own, and which skills it keeps. Read when adding or dropping a skill, or when the Upstream watch finds an idea.
- [ADR 0002](adr/0002-skills-name-model-tiers-not-models.md): skills name cheap, regular or premium tiers, never models; the default tier-to-model map is the `model-tiers` skill, overridden by a project's own map. Read when a skill picks a model or the map changes.
- [ADR 0009](adr/0009-shared-rules-have-one-owner-skill.md): shared-contract ownership, complete workflow reuse, the completed contract and workflow migrations, consumer inventory and continuing consistency protections (amended 2026-11-04, Spec #641: the merge rule is one shared rule, owned by `merging`); menu hiding is optional. - [merging](../../plugins/dev-skills/skills/merging/SKILL.md): the hidden Base skill holding the finish of a pull request: its caller inputs (the pull request and its issue, the merge method and title, who commits, what makes it ready, the caller's own pre-merge step), who merges (from the Boundary record only, empty when missing: the user gets it only at a boundary crossing or when the repo's own rules say a person merges it), the `Agent-merged rules:` line, what the user is told, the repo's merge-time steps run just before any merge, the user's too, the check that the body closes each issue the pull request builds, syncing with main by a merge, the merge with the caller's method, and closing issues only once the merge is confirmed on the tracker. It names no command and no version policy: a bump is a merge-time step of the repo's release doc. `implement` step 7, `implement-spec` step 8 and `release`'s changelog pull request load it, and `review-rounds` defines a boundary crossing by it. Read when changing who merges, the `Agent-merged rules:` line or how a pull request is finished.
- [worker-control](../../plugins/dev-skills/skills/worker-control/SKILL.md): the Base skill a coordinator loads to start, check, stop, pause and resume workers and arrange a check-in: detection by tool names first, role from explicit runtime lineage, one reference per way workers run (`claude-code-project-threads`, `claude-code-sessions`, `codex-subagents`; what each Harness does by itself, and each worker method the coordinator adds with its doc page), the fallback to an unknown Harness's own docs, and the short check. Read when a skill starts, reads, stops, pauses or schedules workers, when adding a way workers run, or when changing Startup verification in a supported Harness.
- [team-lead](../../plugins/dev-skills/skills/team-lead/SKILL.md): the coordinator's delivery role, always a Milestone's (a small Release is a one-Release Milestone): wakes on what workers and the Harness push, starts Release and build threads in order within the slots (Release grouping is `release`'s), follows the repo's merge-time steps, holds a check-in at the Boundary record's interval, from its first build thread, only as a safety net with its `snapshot.py` (one row per worker from the tracker and git, a hand-read fallback, a quiet check-in writing nothing), replaces a stalled worker after one nudge and a stop read back, or parks it and tells the user once, pauses and resumes on the user's word, and takes every worker action through `worker-control`; a coordinator that cannot load the plugin's skills follows the instructions `setup-project` assembles from it and `milestone` instead. Read when changing how delivery runs, its audit-trail records or the snapshot.

Read when changing a review writer or record reader.

- [REVIEW.md](../../REVIEW.md): this repo's review rules: what Important means, what to skip, the 6 Always check lines (each with its origin and file globs, and a retirement rule; the two that check a text's fields, conditions and rerun states are completeness checks of the text) and its Review levels. Read when reviewing a change or adding an Always check line.
- [ADR 0003](adr/0003-code-review-runs-find-verify-rank-in-rounds.md): Round 0 and its Review levels (None, Quick, Standard, Deep), Find, Verify (skipped with nothing to verify) and Rank, at most 3 Rounds (Rounds 2 and 3 on new commits only), disputes, the after-Round-3 sort into bug Tickets, design answers by an agent within the spec, and the review stopping for a person only at a Boundary record crossing; its amendment note records the removed 5-Round loop.
