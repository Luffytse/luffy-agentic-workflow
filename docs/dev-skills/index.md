# Docs index

Read this first, then open only the docs whose line fits your work. Specs and tickets are GitHub issues, not files here.

## Whole repo

- [docs/dev-skills/glossary.md](glossary.md): the words used here (Plugin, Model tier, Spec, Ticket, Release, Implementer, Finder, Verifier, Round 0, Review level, Round, Retro issue, CI, Eval, Case check...). Read when writing or reviewing any skill text.
- [docs/dev-skills/evals.md](evals.md): how a skill change is tested: the three layers (CI, Eval, Review) and the sorting rule, when an eval run is due (a behaviour change runs the skill's cases on the pull request's skill and on main's; wording-only, docs, ADR and eval-only changes skip it and say so on the `**Eval:**` line), no owed runs (the one gap: a run that cannot be made, with its reason), the new case for a skill with no eval, the premium case check, how a thread makes model runs and the fixture self-test rule. Read before opening a pull request that touches skill text or `evals/`, or when writing an eval case.
- [ADR 0013](adr/0013-skill-changes-are-tested-by-ci-evals-and-review.md): why skill changes are tested in three layers (CI deterministic only, an eval run against main's skill on a behaviour change, review for meaning), the sorting rule, and why the plugin carries only a short rule while the method lives in this repo. Read when changing the evals guide, CI's scope or how the plugin speaks of evals.

- [scripts/check-plugin.sh](../../scripts/check-plugin.sh): this repo's own checker for the `dev-skills` layout and repo-wide rules (no vendor model names outside the `model-tiers` skill, no person names, no repo-only text in skill text, no skill naming this repo's version hand-out or Ticket re-read, operations cited as the tracker doc's **Name** or "Name" operation existing in the tracker doc seed, skill name matching its folder, Codex packaging matching Claude Code and sharing its skills tree, each `worker-control` reference method and Harness fact citing a doc page, the `team-lead` skill naming no harness tool, the `milestone` skill naming `team-lead` and holding no harness tool or delivery record kind, no skill file over 5,000 words except the known ones, which may not grow); its header lists the checks, each identified by a name, never a number. A check tests structure and banned names, never that a skill holds a given sentence, so rewording a skill fails CI only if it adds a banned name. It lives outside the plugin so it does not ship to projects. Read when adding or changing a check, or before pushing a plugin change.
- [ADR 0001](adr/0001-dev-skills-is-one-plugin-forked-from-matt-pocock.md): why `dev-skills` is one plugin that began as Matt Pocock's skills and is now our own, and which skills it keeps. Read when adding or dropping a skill, or when the Upstream watch finds an idea.
- [ADR 0002](adr/0002-skills-name-model-tiers-not-models.md): skills name cheap, regular or premium tiers, never models; the default tier-to-model map is the `model-tiers` skill, overridden by a project's own map. Read when a skill picks a model or the map changes.
