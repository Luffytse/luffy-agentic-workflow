# Issue absorption behavioral evaluation

The seam is the actual installed consumer's decisions and fixture artifacts: lifecycle classification, source closing-line selection and absorption publication. These are behavioral runs, not assertions about skill wording. Run only against synthetic tracker facts. Read [RESULTS.md](RESULTS.md) for provenance, outcomes and limitations; the case directories are retained observed outputs, not project instructions.

Use the isolated-home authentication and app-server procedure in [skill loading](../skill-loading/README.md). For this local migration check, install the absolute candidate checkout with `codex plugin marketplace add <checkout>` and `codex plugin add dev-skills@luffy-dev`; do not describe it as a GitHub install. Start a fresh home, fixture and runtime for each case. Select only the discovered consumer skill; never inject the absorption dependency's body. The selected consumer must actually load the installed reference.

- Baseline: archive the pre-migration source into a temporary checkout, install it, select `retro-planning`, and send `lifecycle-prompt.txt`.
- Candidate: install the candidate, select `retro-planning`, and send the same prompt.
- Writer: select `to-tickets`, send `writer-prompt.txt`; only local artifact writes stand in for the configured tracker.
- PR: select `pr`, send `pr-prompt.txt`; inspect the generated lines rather than trusting the final claim.

Preserve exact turns, completed tool items, turn status, discovery and source/cache hashes. Exclude reasoning and authentication. Score all lifecycle rows against the independent issue-state expectations in `score.py`, then inspect the Ticket body for all source-body and comment requirements, links, per-source criteria, and exclusion of the already-closed draft source. `python3 evals/issue-absorption/score.py` scores retained artifacts; it does not rerun an agent. Stop runtimes and delete isolated credentials after saving sanitized evidence.

No real tracker writes or closures are authorized by this fixture. The narrow prompts skip surrounding interviews and planning approval; a full workflow and real tracker transport require separate evaluation. Visibility is separate from discovery/loading/application.
