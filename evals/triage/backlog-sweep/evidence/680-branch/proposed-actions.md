> *This was generated by AI during triage.*

**Triage batch, Release 3.** Category: `bug`. State: `ready-for-agent`. Mark: `next-release`.

Reason: confirmed on main (5f89fa4). Every run appends the name argument to a shared log in `/tmp` and sets that file's mode to 0666, so any user on the machine can read (and rewrite) every name ever greeted, email addresses included. That is a security hole (personal data disclosed to other users), so the issue is severe and must join the next Release. Nothing in the repo reads the log, and no doc gives it a purpose.

## Agent Brief

**Category:** bug
**Summary:** The greeter must stop recording names in a world-readable shared log

**Current behavior:**
Every invocation of the greeter (any command, including an unknown one that prints the usage line) appends the name argument, or `world` when none is given, to `/tmp/greet.log`, then makes that file readable and writable by every user (mode 0666). Names passed by calling scripts, which can be email addresses, are disclosed to every user of the machine.

**Desired behavior:**
The greeter writes no name to any file. It only prints its greeting (or the usage line) as it does today. It changes no file's permissions. Nothing in the project reads the log, so no replacement log is wanted.

**Key interfaces:**
- The greeter's command-line contract (`hello <name>`, `bye <name>`, usage line on stderr with exit 2 for anything else): stdout, stderr and exit codes stay exactly as they are.

**Acceptance criteria:**
- [ ] Running `hello Ada`, `bye Ada`, `hello` with no name, and an unknown command creates no file and appends to none (check that `/tmp/greet.log` is neither created nor changed, starting from it absent and from it present).
- [ ] The greeter changes no file's mode.
- [ ] Output and exit codes for `hello`, `bye`, no name and an unknown command are unchanged.
- [ ] A test in the project's test script covers the first criterion, and the test script passes.

**Out of scope:**
- Removing `/tmp/greet.log` files already left on users' machines (a note for the user, not code).
- The usage line's wording (#30, #36), argument parsing (#40) and any other greeter behavior.
~~~

## Brief (for the user's decision)

**Category:** enhancement
**Summary:** Add a `--json` output mode giving calling scripts a stable output shape

**Why it can't be delegated yet:** it is a new feature an agent proposed, outside Milestone 1's listed features; whether to build it, and its exact shape, are the user's design decisions.

**Current behavior:**

**Desired behavior (if the user accepts it):**
With `--json`, the greeting is printed as one JSON object, e.g. `{"greeting": "Hello, Ada!"}`; without it, output is byte-for-byte unchanged.

**Decisions for the user:**
- Build it at all, and in which Milestone.
- Where the flag goes (after the name, as the quiet flag #20 does, which needs #40 first) and how it combines with `-q`.
- Whether errors (the usage line) also come out as JSON under `--json`, and with which exit code.

**Acceptance criteria (draft):**
- [ ] `hello Ada --json` and `bye Ada --json` print a single valid JSON object holding the greeting.
- [ ] Output without `--json` is unchanged.
- [ ] Tests cover both commands with the flag.

**Out of scope:**
- Other output formats; colour (#51).
