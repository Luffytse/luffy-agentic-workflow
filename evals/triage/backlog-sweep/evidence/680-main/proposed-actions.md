Issue: 41-name-log.md
Body:
~~~
> *This was generated by AI during triage.*

**Triage batch, Release 3 (#4).** Decision: category `bug`, state `ready-for-agent`, mark `next-release`.

Reason: confirmed. Every run of `greet.sh` (any command, including an unknown one, which logs `world`) appends the name argument to `/tmp/greet.log` and then sets that file to mode 0666. Reproduced on main (5f89fa4): `greet.sh hello ada@example.com` left `ada@example.com` in a `-rw-rw-rw-` log. The line has been there since the first commit (#5). Nothing in the repo reads the log, and no test or doc asks for it. Personal data (email addresses) readable and writable by every user on the machine is a security hole, so the issue is severe and gets `next-release`.

## Agent Brief

**Category:** bug
**Summary:** greet.sh must stop recording the names it greets in a shared, world-readable file

**Current behavior:**
On every invocation, before the command is dispatched, the script appends the name argument (or the default `world`) to `/tmp/greet.log` and runs `chmod 666` on that file. Any local user can read the names passed in (some callers pass email addresses), and can also write to or replace the file.

**Desired behavior:**
Running `greet.sh` with any arguments writes the greeting (or the usage line) and nothing else: no name is written to any file, and the script changes no file's permissions. The printed output and exit codes of `hello`, `bye` and the usage error stay exactly as they are now.

**Key interfaces:**
- The `greet.sh` command line: `hello <name>`, `bye <name>`, and the usage error with exit code 2. Its stdout, stderr and exit codes are unchanged.
- The logging side effect (append name to a shared log, then make it mode 0666) is removed, not moved or re-permissioned.

**Acceptance criteria:**
- [ ] `greet.sh hello Ada`, `greet.sh bye Ada` and `greet.sh x` create no file and modify no existing file (a test checks that a pre-existing `/tmp/greet.log` is not appended to, or the equivalent with the path the script used)
- [ ] The script runs no `chmod` and writes to no path outside stdout and stderr
- [ ] `bash test.sh` passes, with a new assertion covering the first criterion
- [ ] Output and exit codes of `hello`, `bye` and the usage error are unchanged

**Out of scope:**
- Deleting an existing `/tmp/greet.log` on users' machines (the change cannot reach them; mention it in the PR body instead)
- Adding any replacement logging or audit feature
- The usage-line typo (#30), the usage line missing `bye` (#36) and argument parsing (#40, #34)
~~~

## Brief

**Category:** enhancement
**Summary:** Add a `--json` flag that prints the greeting as a JSON object

**Why this cannot be delegated:** it is a new feature an agent proposed; whether the greeter should have a machine-readable output mode, and with what shape, is the user's product decision. Once the user accepts it, it can move to `ready-for-agent` with this brief.

**Current behavior:**
`greet.sh hello <name>` and `greet.sh bye <name>` print a plain-text line; callers that need the greeting parse that text.

**Desired behavior (if accepted):**
With `--json`, the command prints one JSON object such as `{"greeting": "Hello, Ada!"}` on stdout. Without the flag, output is unchanged.

**Key interfaces:**
- The `greet.sh` command line gains a `--json` option, read after the name. It depends on the script reading arguments after the name at all, which is #40.
- Open decisions for the user: the object's fields, how the usage error is reported under `--json`, and whether `-q` (#20) combines with it.

**Acceptance criteria (if accepted):**
- [ ] `greet.sh hello Ada --json` prints valid JSON with the greeting text
- [ ] `greet.sh bye Ada --json` does the same for the farewell
- [ ] Without `--json`, output and exit codes are byte-for-byte unchanged
- [ ] `bash test.sh` covers the JSON output

**Out of scope:**
- Other output formats
- Changing the plain-text greeting
