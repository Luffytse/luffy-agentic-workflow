Issue: 41-name-log.md
Body:
~~~
> *This was generated by AI during triage.*

Triage batch, Release 3.

## Agent Brief

**Category:** bug
**Summary:** Stop writing every name given to the greeter into a world-readable log file.

**Current behavior:**
Every run of the greeter, whatever the command (including an unknown one), appends the name argument (or `world`) to `/tmp/greet.log` and sets that file's mode to 0666. Any user on the machine can read, and also overwrite, the names passed in; some callers pass email addresses as the name. Reproduced on main (5f89fa4): after `greet.sh hello Ada`, `/tmp/greet.log` has mode 666 and ends with `Ada`. The write has been there since the first commit (1052f65).

**Desired behavior:**
Running the greeter leaves no record of the name anywhere other users can read. No feature in the Milestone or any open issue needs the log, so the simplest fix is to drop the write and the mode change entirely. Output and exit codes of every command are unchanged.

**Key interfaces:**
- The greeter's commands `hello <name>` and `bye <name>`, and the usage error path (exit 2): stdout, stderr and exit code must stay byte-for-byte the same.

**Acceptance criteria:**
- [ ] With `/tmp/greet.log` absent, running `hello Ada`, `bye Ada` and an unknown command creates no `/tmp/greet.log` and no other file holding the name.
- [ ] With a pre-existing `/tmp/greet.log`, a run neither appends to it nor changes its mode.
- [ ] `bash test.sh` passes, and a test covers the first criterion.

**Out of scope:**
- Deleting or cleaning up a `/tmp/greet.log` left by earlier versions (mention it in the pull request so users can remove it).
- Adding any new logging or audit feature.
- Other open bugs in the usage line or argument handling (#30, #33, #34, #36, #40).
~~~

- [ ] The same holds for `bye`.
- [ ] Without `--json`, output and exit codes are byte-for-byte unchanged.
- [ ] A test covers both commands with `--json`.

**Out of scope:**
- Other output formats; colour (#51).
