**Summary:** Listing orders makes one database query per order and is slow with many orders

**Current behavior:**
`list_orders(db)` gets the list of order ids and then fetches each order with a separate call, so 10,000 orders cost 10,000 queries and the endpoint takes about 4 seconds.

**Acceptance criteria:**
- [ ] `list_orders` returns exactly the same orders in the same order as before
- [ ] The number of database calls does not grow with the number of orders (a test with a counting fake database shows it)
- [ ] An empty order list still returns an empty list

**Out of scope:**
- Pagination of the endpoint
- Caching
- Changes to the order data shape
