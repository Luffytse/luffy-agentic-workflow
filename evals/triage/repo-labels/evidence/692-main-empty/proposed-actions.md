## Agent Brief

**Category:** bug
**Summary:** Orders list makes one database query per order

**Current behavior:**
`list_orders` fetches the order ids and then asks the database for each order separately, so the number of queries grows with the number of orders (10,000 orders mean 10,000 queries, about 4 seconds as reported).

**Desired behavior:**
`list_orders` returns the same orders in the same order, fetching them with a constant number of database queries that does not grow with the number of orders.

**Key interfaces:**
- `list_orders(db)` return value: must stay the same list of orders, in the same order.
- The database object `db`: its API may gain a way to fetch many orders at once; the existing per-order call must keep working for other callers.

**Acceptance criteria:**
- [ ] `list_orders` returns exactly the same result as before for 0, 1 and many orders
- [ ] The number of queries `list_orders` makes is the same for 10 orders as for 10,000 (a test counts them)
- [ ] Listing 10,000 orders no longer takes seconds in that test setup

**Out of scope:**
- Pagination of the orders list
- Caching
- Changes to other endpoints
~~~
