**Category:** enhancement
**Summary:** Listing orders must fetch them in a constant number of database queries, not one per order

**Current behavior:**
The orders listing function walks the list of order ids and asks the database for each order separately, so N orders cost N+1 queries. With 10,000 orders the endpoint takes about 4 seconds. Verified by reading the code: one `db.order(oid)` call per id in a loop.

**Acceptance criteria:**
- [ ] The listing returns exactly the same result as before for the same data
- [ ] The number of database calls does not grow with the number of orders (a test with a counting fake database shows the same count for 10 and 1,000 orders)
- [ ] An empty order list still returns an empty list

**Out of scope:**
- Pagination or caching of the listing
- Changes to the order data shape
- Other endpoints
~~~
