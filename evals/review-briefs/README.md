# Review brief script tests

`test_review_briefs.py` tests `plugins/dev-skills/skills/review-rounds/review_briefs.py` as a command. Each test builds a scratch git repo with a planted change, writes the spec, standards list, earlier Findings and design answers to files, runs `review_briefs.py` (`round1`, `ticket`, `fixed`, `later`, `verify` or `disputes`) and reads the briefs back. No agent runs.

Run: `python3 evals/review-briefs/test_review_briefs.py` (Python 3 and git only). Run it after changing the script or the brief files it cuts from (`FINDERS.md`, `DEEP.md`, `SKILL.md` of `review-rounds`, `review-record`, `docs-index`).

A test checks what a brief holds against the skill files read the same way (a section present or absent, an Always check line included or left out, the Finders the table names for each level), never a sentence of a skill's wording, so rewording a skill does not fail it. Cases: who runs at each level, with and without a spec; each Finder's sections and the ones it must not get; Always check lines by `(files: ...)` globs, `(files: all)` for every diff, the shipped template's example line read back by name and globs, and a line with no file scope still included with a warning on stderr; the smell baseline only for code; the docs index check only with an index; defaults without `REVIEW.md`, a Boundary record or an index; the angle by name and an unknown angle; a missing section stopping with exit 3 and its name; usage errors (exit 2); an output directory inside the work tree refused; only `git` called; nothing written outside the output directory.

The `verify` cases: a report with several Findings and Locations carried over byte for byte under its Finder; a missing, empty or off-format report (a Finding lacking a field of the format, a section-label heading, a second `## Notes`, a Finding after `## Notes`) stopping with exit 3, every such Finder named and the Report format rule in the message, nothing written; a report with Findings and a `## Notes` section passing with the notes not counted as Findings, and a nothing-found report with notes counting as nothing found; reports read from `<out>/reports` when `--reports` is left out; a report of a Finder the arguments leave out refused naming it; the plain "no issues found" variants accepted, and a nothing-found line with a short explanation after `:`, `.` or ` - ` (a line merely containing the words, or an explanation with no separator, still refused); all "nothing found" with no earlier Finding writing no Verifier brief; the Verifier brief with its tier (premium at Deep) in the printed list; only the Always check lines a candidate's Bug class names.

The Finder briefs: each carries the Report format and its own report file path (`<out>/reports/<finder>.md`, `later.md` for a later-Round Finder), a rerun removing a stale report file, and the Verifier brief carries the Report format.

The other kinds of Round, one subcommand each: `later` (Round 2 or 3: one `finder-later.md` holding both Finders' inputs and briefs, the new-commits diff from the last head and the new-commits sentence, premium tier with the security brief at Deep, no spec brief without a spec, a merge from main showing no main-only commit in the commit list); `verify --for later` (expects `later.md`, names Round 2 or 3, not Round 1); `disputes` (only `verifier.md`, holding the Verifier brief, the copy rule, the head, the disputes, the meaning of Important and the Skip list, and none of the spec, design answers, diff or Always check lines; an empty disputes file is a usage error); `ticket` (the Quick Round 1 briefs for the Ticket branch against the Spec branch, no `--level`, `verify --for ticket`); `fixed` (the Round 1 briefs since a commit, tag or branch, the working tree counted, untracked new files listed and counted for the files' globs, `verify --for fixed`).
